# DEEPFLAT 부가 설명 문구 덱

2026-10-27 · 요청 3(스튜디오 세 항목)과 요청 4(친근한 말투)를 위한 문구 모음입니다. 기계가 읽는 같은 내용은 `copy-deck.json`에 있습니다.

## 말투 기준

해요체 (친근하고 믿음 가는 말투). 집을 맡길 가족에게 담당 디자이너가 직접 설명하는 목소리.

- 문장 끝은 해요체로 통일: ~해요 / ~예요·이에요 / ~드려요 / ~주세요. 합쇼체(~습니다)와 섞지 않는다.
- 큰 제목(디스플레이)은 그대로 둔다. "집의 깊이를 설계합니다"는 사용자가 승인한 제목이라 바꾸지 않는다.
- 짧은 문장, 생활 단어: 조명·마감재·견적서·현장·공정 이름(철거·설비·목공·전기·타일·도장)처럼 사람들이 아는 말.
- 문어체 연결(~기에, ~하여)과 추상 표현(빛이 머무는, 하루를 내려놓는, 호텔 같은)은 쓰지 않는다.
- 새 약속 없음: 무료·보증·최저가·100% 같은 말은 원래 있던 "첫 상담 무료" 말고는 넣지 않는다.
- 모든 "예시"·"데모"·"시안" 표시는 그대로 지킨다. 렌더(그림·미니어처)를 실제 사진처럼 말하지 않는다.
- 연결어미(-고, -서, -면서) 바로 뒤에 쉼표를 찍지 않는다. 느낌표·이모지 없음.

## 브랜드 문단 (요청 4)

**지금:** 한 집을 맡으면 빛이 드는 방향과 가족의 하루, 오래 손에 닿을 재료부터 살핍니다. 처음 도면을 그린 디자이너가 마지막 마감까지 현장을 지키기에, 도면 속 장면이 그대로 집이 됩니다.

**바꿀 문장:** 집을 맡으면 해가 드는 방향과 가족의 하루, 오래 손에 닿을 재료부터 살펴봐요. 처음 도면을 그린 디자이너가 마지막 마감까지 현장을 지켜요. 그래서 도면에서 함께 본 장면이 그대로 집이 돼요.

원문은 "~기에,"(문어체 이유 연결)와 "빛이 드는 방향" 같은 글말 때문에 딱딱했다. 해요체로 바꾸고, 긴 이유 문장을 짧은 두 문장으로 나눴다. 뜻(해가 드는 방향·가족의 하루·오래 손에 닿을 재료를 먼저 본다 / 도면 그린 디자이너가 마지막 마감까지 현장을 지킨다 / 그래서 도면 속 장면이 그대로 집이 된다)은 그대로다. "도면 속 장면"은 가족이 설계 때 디자이너와 같이 보는 장면이라 "도면에서 함께 본 장면"으로 풀었다(새 약속이 아니라 설계 단계를 말로 옮긴 것).

다른 안:

- 집을 맡으면 먼저 해가 어느 쪽에서 드는지, 가족이 하루를 어떻게 보내는지부터 살펴봐요. 오래 손에 닿을 재료도 그때 같이 살펴요. 처음 도면을 그린 디자이너가 마지막 마감까지 현장을 지키니까 도면에서 본 장면이 그대로 집이 돼요. (더 말하듯 풀었다. 약 20자 길다.)
- 집을 맡으면 해가 드는 방향과 가족의 하루, 오래 손에 닿을 재료부터 살펴봐요. 도면을 그린 디자이너가 마지막 마감까지 현장에 있으니까 도면 속 장면이 그대로 집이 돼요. (두 문장으로 짧게. 원문보다 약 10자 짧다.)

첫 문단은 끝말만 바꿉니다: 딥플랫은 아파트와 단독주택을 설계하고 시공하는 하이엔드 주거 인테리어 스튜디오예요. 이름에는 깊이(DEEP)와 집(FLAT), 두 단어를 담았어요.

### 그림 기준 (그림 담당에게)

- **설계한 디자이너가 시공까지**: 같은 작은 디자이너 인물이 두 번 나온다. 왼쪽은 책상 위에 평면도 도면을 펼쳐 그리는 장면, 오른쪽은 안전모를 쓰고 같은 도면을 든 채 공사 중인 방(목재 골조가 드러난 벽, 사다리, 쌓아 둔 타일) 앞에 선 장면. 두 장면을 점선 발자국이나 길로 이어 "도면 그린 사람이 현장에 간다"가 한눈에 읽히게.
- **공정별로 나눈 견적서**: 받침 위에 놓인 미니어처 견적서(클립보드 종이) 한 장. 여섯 줄마다 맨 앞에 그 공정을 알아볼 작은 물건을 둔다: 철거=망치와 깨진 벽돌, 설비=수도 배관 엘보·수전, 목공=각재와 톱, 전기=스위치와 전선, 타일=타일 격자, 도장=페인트 롤러. 줄 오른쪽에는 수량×단가 칸(짧은 막대나 숫자 자리)과 맨 아래 합계 줄. 공정 이름을 아주 작게 한글로 붙여도 좋다.
- **조명과 마감재**: 창이 있는 방 한 모서리. 천장 펜던트와 매입등 두 개가 바닥에 따뜻한 빛 원뿔을 떨어뜨리고, 그 옆에 따뜻한 색에서 하얀 색으로 넘어가는 작은 색온도 띠. 빛이 떨어진 바닥에는 마감재 샘플을 부채처럼 펼쳐 둔다: 원목 마루 한 조각, 타일 한 장, 페인트 색 칩 묶음. "조명과 마감재를 현장 빛에서 고른다"가 읽히게.

제목을 바꾼 이유:

- 설계한 디자이너가 시공까지: "사람" 대신 "디자이너"라고 누가 맡는지 바로 말한다. 설계·시공은 고객이 아는 단어라 유지.
- 공정별로 나눈 견적서: "항목"이 무엇인지 모호하다. 고객이 받아 보는 물건인 "견적서"와, 무엇으로 나뉘는지("공정별")를 제목에 넣었다.
- 조명과 마감재: 사용자 제안 그대로. "빛과 재료"는 감성어라 무엇을 하는지 안 보이고, "조명과 마감재"는 공사에서 실제로 고르는 두 가지다.

## 적용 방법

1. 각 entry의 locations를 순서대로 적용한다. kind=source/static은 그 파일을 직접 고치고(find → replace, expect만큼 모두), kind=generated는 손대지 않는다.
2. 데이터를 고친 뒤 deepflat 폴더에서 node final/svg/build.mjs --target index.html 을 실행해 GEN 블록(flight, carousel, pf-data)을 다시 만든다.
3. 적용 뒤 find 문자열이 남아 있지 않은지 검사한다(이 덱의 locations로 바로 확인 가능).
4. 390-1440px에서 바뀐 곳을 본다: 스튜디오 제목 줄바꿈(<br> 위치), 착공 가능 일정 설명 두 줄 안쪽, 브랜드 둘째 문단 줄 수.

파일별 찾기·바꾸기 목록(어느 파일의 어떤 문자열을 몇 번)은 `copy-deck.json`의 각 entry `locations`에 있습니다. `kind: generated`는 GEN 블록 안이라 직접 고치지 않고 build로 다시 만듭니다.
